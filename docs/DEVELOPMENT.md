# DEVELOPMENT.md — installation and troubleshooting

The work rules, gates and verification commands live in `AGENTS.md`. This
document only covers how to prepare and diagnose the local environment.

## Stack

| Layer | Tool |
|---|---|
| RTL | SystemVerilog compatible with Verilator |
| Simulation | cocotb + Verilator; Questa/Vivado xsim if needed |
| HDL style | `verible-verilog-lint` |
| Golden | Python 3.11+ |
| Synthesis | Vivado for UltraScale+ |

## Setup

```bash
# cocotb 2.0.1 does not support Python >= 3.14.
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

verilator --version
cocotb-config --version
python -c "import cocotb, numpy; print('cocotb', cocotb.__version__)"
```

## Reference commands

| Gate | Reference command |
|---|---|
| A. Simulation | `make -C verification/<area> sim` (or `cocotb-config` + verilator makefile) |
| A. Simulation (phase 0, Python) | `python3 -m unittest discover -s golden_model/tests -t .` |
| B. Compilation/lint | `verilator --lint-only -Wall --top-module <module> rtl/<area>/<file>.sv` |
| C. Style | `verible-verilog-lint --rules_config_search rtl/<area>/<file>.sv` |
| D. Functional coverage | Verilator/Questa coverage report + spec↔test table (gate D level 1) |
| E. HDL mutation | mutation runner over `rtl/<area>` (flip guard/comparator → a test must kill it) |
| F. Completeness | `specs/gherkin-espejos.json` consistent + literal mirror test titles |
| G. Timing/resources | Vivado: `synth/` project, WNS/TNS report and LUT/FF/BRAM/URAM utilization |

### Gate C — verible

`verible-verilog-lint` (and `verible-verilog-format`) is installed in
`.venv/bin` from the official Verible release
(`chipsalliance/verible/releases`, tarball `*-macOS.tar.gz`). There is no brew
formula or pip package; the binaries are copied over:

```bash
# download verible-vX-macOS.tar.gz from the ChipsAlliance/verible release,
# extract, and copy the binaries to the project's venv:
cp verible-*/bin/verible-verilog-lint verible-*/bin/verible-verilog-format .venv/bin/

# run the lint (uses the repo's config, root):
verible-verilog-lint --rules_config_search rtl/parser/mdp3_parser.sv
```

The repo ships the config in `./.rules.verible_lint` (flat format of
`--print_rules_file`): it aligns the `parameter-name-style` rule with the
project's SCREAMING_SNAKE convention (do not rename constants of verified RTL)
and keeps the genuine consistency rules active.

## Known problems

- If `cocotb-config` does not exist, the Python environment is not activated or
  `requirements-dev.txt` was not installed; the RTL Makefiles cannot start.
- **Vivado ML 2023.2 IS available on the work PC (Windows,
  `C:\Xilinx\Vivado\2023.2`)** since the 2026-08-18 run: `vivado -mode batch
  -source synth/fase3_synth.tcl` and the reports are saved in
  `synth/reports/`. It is not on the PATH: invoke
  `C:\Xilinx\Vivado\2023.2\bin\vivado.bat` (or `xvlog.bat` for a fast RTL parse
  without Verilator: `xvlog --sv --nolog <file>.sv`; in isolation it reports a
  pre-existing false positive of `nx_done` used before its declaration — legal
  in SV, does not block the parse). On the development machine (macOS) Vivado
  is NOT installed; only the simulation gates (A/E/B/C) run there.
- Real data and pcaps are local and ignored by Git; the testbenches read
  vectors from `verification/vectors/` or ignored local artifacts. A replay
  omitted because a pcap is absent does not count as a real-data PASS.
- `scripts/verify/synth_check.py` checks static coherence between RTL/Tcl/XDC;
  it does not replace a Vivado run. Without `vivado`, WNS, TNS and utilization
  remain NOT EXECUTED and phase 3 is not timing-closed.
- **Phase 3 parameters are overridden from the top**: `itch_chain.sv` declares
  its own `QB` (and others) and passes them to the modules with `.QB(QB)` —
  changing a module default does NOT affect the chain (2026-08-14 finding:
  "QB 64" in `itch_parser.sv` did not move the latency; the binary elaborated
  128). The effective parameter lives in the top and in the Makefile's `-G`
  line. Before measuring a parameter change, confirm WHICH module elaborates
  the value (cocotb trace of internal signals or inspection of the C++
  constants generated by Verilator).
- `verible-verilog-lint` is installed (`.venv/bin`, see Gate C above); always
  use it with `--rules_config_search` to respect the repo's config. The style
  of the phase 1-3 RTL still reports convention findings (it is closed and
  verified constants are not renamed); the phase-4 gate C covers
  `mdp3_parser.sv`.
- Each campaign preserves real outputs and non-executed gates in
  `specs/<campaign>/verify-report.md`. A gate without output is not passed.
